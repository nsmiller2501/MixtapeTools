# Key Decisions — MixtapeTools Skill Development

Durable decisions for Claude/Codex skill architecture. These are tracked in git and should survive branch deletion, rollbacks, and session-log churn. Append new entries; do not rewrite history except to fix factual errors.

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-05-16 | Keep `progress_logs/` ignored; use tracked `agent_memory/` for durable project memory. | Progress logs are session continuity artifacts and branch-local scratch history. Tracking them would couple living logs to branch rollbacks. Durable decisions should be promoted here instead. |
| 2026-05-16 | Keep `/handoff` and `/session end` as separate skills. | `/session end` is project-rooted, writes dated progress logs, and updates `agent_memory/`; `/handoff` is an ephemeral baton-pass outside the project-memory lifecycle. |
| 2026-05-16 | Make `/read-pdf` canonical and keep `/split-pdf` as compatibility wrapper. | The two skills shared an output contract and duplicated schema/isolation docs. `/read-pdf --split` preserves the legacy vision-batch backend while reducing maintenance drift. |
| 2026-05-16 | Keep one `/referee2` router; split code mode internally by phase. | `referee2.md` is the right shared persona/common resource for deck, code, and future referee-audit types. The real load problem was the 53KB code-mode protocol, now a small `code.md` index plus progressive-disclosure phase files. |
| 2026-05-18 | Make `/read-pdf` own a reusable extraction substrate for converted markdown. | Marker `markdown.md` can exceed Read limits and cause prompt cache amplification in both `/read-pdf` and `/wiki-update`. The substrate should be a separate lazy script that creates structural chunk files plus a manifest from existing cache output, without reconverting PDFs or interpreting paper content. |
| 2026-05-18 | Prefer fanout-first extraction for academic-paper marker mode. | The expected workload is long, dense academic PDFs, so size-gating between single-agent and fanout paths adds complexity and can miss short but token-dense papers. Chunk workers should read bounded source segments; a synthesis bottleneck should write paper-level artifacts. |
| 2026-05-18 | Use `references/references.bib` for wiki citation-overlap candidates. | `wiki-update` already refreshes this BibTeX file via `/bib-update`, making it the clean registry of ingested papers. Mechanical overlap checks against a new paper's references can suggest related existing papers without forcing the synthesis agent to treat them as authoritative links. |
| 2026-05-18 | Keep `_text.md` project-neutral across `/read-pdf` and `/wiki-update`. | `_text.md` should be the reusable source-of-truth paper extract regardless of entrypoint. `wiki-update` should use one synthesis bottleneck to write that neutral extract and then apply project context when writing wiki pages, avoiding a second wiki-specific synthesis agent that could miss details. |
| 2026-05-19 | Run fanout workers sequentially by default. | Sequential fanout preserves the token-safety benefits of bounded worker contexts while limiting usage-cap blast radius: if a limit is hit mid-ingest, at most one worker's active bundle is lost rather than several parallel workers. Parallel fanout can be an explicit later mode if speed becomes more important than usage-limit containment. |
| 2026-05-22 | Use Obsidian task boxes for `/session end` task recording. | Background task aggregation depends on literal markdown checkbox prefixes: `- [ ]` for outstanding tasks and `- [x]` for completed tasks. `agent_memory/tasklist.md` is read-only except for marking existing tasks complete. |
| 2026-05-23 | Upstream PRs to Scott's repo follow a one-follow-on-per-prior-PR stacking model. | Every skill in scope already has a pending PR on Scott's queue. Branching each new follow-on PR off its corresponding prior PR's head (or `upstream/main` for bibcheck, the only truly merged skill) keeps the diff a clean delta. GitHub shows cumulative changes until the predecessor merges, then auto-narrows. Branch naming: `followup/<topic>`. |
| 2026-05-23 | Defer the six "new" skills (caveman, grill-with-docs, handoff, newproject-git, session, write-a-skill) from the second upstream PR round. | First-pass usage audit on /caveman showed actual output-token savings of ~8% median / ~23% mean / ~25% p90 vs the skill's advertised ~75%. Need more usage data on the rest before deciding which warrant upstreaming. Re-audit window targeted for 2026-06-13. |
| 2026-06-03 | Make `/caveman` opt-in; remove it from `/session start`. | Global CLAUDE.md §6 now mandates passive concision (incl. chat responses) as the always-on default. `/caveman` is a heavier, summonable compression mode with safety carve-outs — keeping it auto-on at session start blurred the two. Default = §6 floor; caveman = on-demand gear shift. |
| 2026-06-03 | Drop the `latex_path` gate from the prereview hook; keep `wrong_python`. | Verified texbin is reliably on PATH for agents via `/etc/paths.d/TeX` (inherited by every subshell incl. `zsh -f`), so bare `pdflatex` works — the gate guarded nothing functional and listed 4 bins (lualatex/xelatex/biber/bibtex) no skill invokes. `wrong_python` stays: silent `/usr/bin/python3` (3.9 stub) wastes a turn. |
| 2026-06-03 | Track the personal global config at `.claude/CLAUDE.md`; symlink `~/.claude/CLAUDE.md` + `~/.codex/AGENTS.md` to it. | Version-controls future edits. `.claude/` (not root, not `claude/`) mirrors the `~/.claude/` global layout so a clone lands skills + config together, and avoids double-loading as project instructions. `claude/CLAUDE.md` is a separate upstream template left untouched to avoid PR diff-dust. Also trimmed the global Program Paths table to just the `/usr/bin/python3` warning + symlinked `stata-se` into `/usr/local/bin`. |
